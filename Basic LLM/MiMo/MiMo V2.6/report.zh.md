## 摘要

强化学习（Reinforcement Learning, RL）是推动大型基础模型迈向自我改进（self-improvement）的核心训练范式。本报告介绍 **MiMo-V2.6 系列**——一个全模态（omni-modal）模型家族，通过扩大 RL 计算规模推动模型智能前沿。在进入 RL 之前，我们先在大规模多模态语料上做 **中期训练（mid-training）**，为智能体提供充足的探索空间，并在预训练的混合 SWA 架构上构建坚实基础设施，以支撑后续扩展。

我们将 RL 计算沿三个维度扩展：

1. **更大 batch 与更高吞吐**：异步训练每步消耗 1,568 个样本、约 2.7～3.7B token，上下文长度可达 1M；
2. **更丰富、更复杂的环境**：覆盖代码、通用、视觉与网络安全等领域，并混合多种智能体脚手架（agent harness）；
3. **更多评分器计算**：通过组级智能体评分（groupwise agentic grading），为长时程任务提供更准确的奖励信号，并引导模型产出更短、更省 token 的解法。

为保持大规模训练稳定，我们冻结 MoE 路由器（router），并建立针对奖励作弊（reward hacking）的多层防御。我们还构建了混合任务智能体 RL 基础设施，包括统一轨迹表示、高并发多框架 rollout、控制面与数据面解耦，以及训练–推理一致性。我们开源训练动态、RL 环境与 RL 框架，以促进可复现研究与扩展 RL / 模型自我改进方向的后续工作。

## 1. 引言

递归自我改进（Recursive Self-Improvement, RSI）设想模型通过持续探索与反馈扩展自身能力。实现这一愿景需要**智能体（agents）**：把模型与交互式环境耦合，从而提供自我改进所依赖的多步轨迹与反馈信号。在复杂智能体任务上扩展强化学习，由此打开一条具体路径。然而，将这一潜力落地面临两大挑战：其一，面向基础模型的 RL 需要合适的模型架构，以及足够丰富的智能体探索空间；其二，扩展 RL 需要在基础设施、环境与评分器（grader）上具备成熟方案。

本报告介绍 **MiMo-V2.6 系列**，包括：

| 型号 | 总参数 | 激活参数 | 结构 |
| --- | ---: | ---: | --- |
| **MiMo-V2.6-Pro** | 1.02T | 42B | Mixture-of-Experts (MoE) |
| **MiMo-V2.6-Flash** | 310B | 15B | Mixture-of-Experts (MoE) |

MiMo-V2.6 的架构、预训练与中期训练共同建立强大而高效的基础模型。为在较低计算成本下保留全局上下文，骨干网络采用**混合稀疏 MoE Transformer**：交错局部滑动窗口注意力（Local Sliding Window Attention, SWA）与全局注意力（Global Attention, GA），并辅以轻量视觉编码器与音频编码器。大规模预训练赋予模型广泛知识与跨文本、音频、视频的多模态理解能力。我们进一步引入以智能体为中心的**中期训练**阶段，扩展智能体任务的探索空间，使模型在后训练中能发现更有效的任务求解轨迹。

随后，我们通过协同设计的框架，在三个关键组件上扩展 RL 计算：

1. **扩大 batch 与训练吞吐**：完全异步训练，在上下文最长 1M 时每步处理数千条长时程 rollout 与数十亿 token；
2. **扩展 RL 环境的多样性与复杂度**：覆盖代码、通用、视觉与网络安全任务，使用多种智能体 harness，并加强针对奖励作弊的防护；同时改变 harness 与任务有利于提升泛化；
3. **组级智能体评分（Groupwise Agentic Grading）**：在二值测试用例之外提供更有信息量的奖励。并非所有通过测试的解都拿到相同奖励，而是在**同一组**内比较解的质量与行为。通过提出的 **组级奖励合成（Groupwise Reward Synthesis, GRS）** 与 **组级优势再分配（Groupwise Advantage Redistribution, GAR）**，把细粒度差异转化为更有信息量的学习信号，引导模型给出更准确、更高效的解法。

把上述能力扩展到大规模，对基础设施提出研究与工程双重挑战。为支持灵活的智能体交互，我们设计**统一轨迹表示**与惩罚机制以细化学习信号；为承载超大训练 batch，通过 harness 池维持跨多种智能体框架的高并发交互，并解耦控制面与数据面以缓冲、传输携带路由与多模态负载的海量轨迹。**样本混合（Sample Mixer）** 机制与动态采样、部分 rollout 协同，稳定训练 batch 中各任务的样本构成。我们对齐训练与推理引擎在 MoE 路由与 top-p 采样候选集合上的行为，并针对 RL 负载优化两端引擎。

扩展 RL 计算显著释放了模型在可验证任务（如编码）与较难验证任务（如 Web 开发）上的潜力。如图 1 所示，MiMo-V2.6-Pro 与 MiMo-V2.6-Flash 随训练步增加，在所报告基准上持续提升，且收益不局限于单一领域，在 DeepSWE 编码、AutomationBench 通用工作流、MiMo Visual Coding 视觉任务与 MiMo Cyber Bench 网络安全上均保持一致。这表明 MiMo-V2.6 在复杂问题求解与日常协作场景中更可靠，体现更通用的智能体智能。

为推动智能体 RL 研究，我们开源覆盖 RL 开发栈关键组件的一整套工具，包括轻量模型 **MiMo-V2.6-Distill-Qwen-9B**、多领域带验证器的任务环境、端到端 RL 训练框架，以及可组合的 mini-harness，便于灵活智能体交互。MiMo-V2.6-Distill-Qwen-9B 上的实验表明，跨多样任务与 harness 均有一致 RL 收益，验证该套件的有效性与通用性。我们希望这套开源组件能成为社区公平、强健、可复现的基线。

## 2. 架构

### 2.1 总体架构

如图 2，MiMo-V2.6 采用标准 Transformer 骨干，并经轻量投影层接入视觉与音频编码器。文本骨干主要由重复的**混合块**构成，交错 SWA 与 GA：堆叠 \(M\) 个混合块，每个混合块内为 \(N\) 个连续 SWA 块后接 1 个 GA 块。例外是**最前一个 Transformer 块**：使用全局注意力与稠密前馈网络（FFN），以稳定早期表示学习。MiMo-V2.6 的滑动窗口大小 \(W=128\)。SWA 块与 GA 块均使用**无共享专家**的稀疏 MoE FFN。

MiMo-V2.6 还集成了基于 SWA 与稠密 FFN 的 **MTP（Multi-Token Prediction）** 模块，以提升预训练表现。完整文本骨干说明见 Core Team et al. (2026)。模型配置见表 1。

### 2.2 MiMo-ViT

MiMo-ViT 采用混合注意力架构：将 MiMo-VL-7B 中固定、非重叠的窗口注意力替换为带 sink 的 SWA，使信息能在连续层间跨窗口边界交换，缓解视觉碎片化。局部 SWA 层在行优先与列优先 token 序列化之间交替，支持沿两个空间轴传播信息；并周期性插入 GA 层直接聚合全局上下文。该设计大幅降低高分辨率视觉处理的计算成本，同时达到与 GA ViT 相当的性能（详见 He et al., 2026）。

为从零预训练 MiMo-ViT，我们将其与小型预训练 LLM 配对，仅用多模态理解数据、以交叉熵目标优化得到的 VLM。该简单配方避免对比学习等辅助目标，使预训练高效可扩展。关键是 **LLM 保持可训练**，从而为 ViT 提供稳定、语义有意义的梯度。在超过 4T 图像 token 上预训练后，MiMo-ViT 学到强视觉表示，成为 MiMo-V2.6 的稳健基础。

### 2.3 音频编码器

音频编码分两阶段：先用 **Audio Tokenizer** 做音频分词，再做 patch 编码。

**Audio Tokenizer 编码器：** log-mel 频谱先经两层卷积前端（帧率减半），再进入因果混合注意力 Transformer（交错 SWA/GA）。SWA 捕捉局部时间依赖，GA 聚合此前完整序列上下文。随后下采样卷积将帧率再降至 **25 Hz**，20 层残差向量量化（RVQ）将每帧表示为 20 个离散音频 token。训练配方沿用 MiMo-Audio，在涵盖语音、音乐等的 **2000 万小时**音频上训练。

**音频 patch 编码器：** 架构对齐 MiMo-Audio，与文本骨干联合训练。每个时间步上，各 RVQ 码本使用独立嵌入表得到嵌入并求和，形成单帧表示。每连续 4 帧组成一个音频 patch，由注意力限制在该 patch 内的双向自注意力 Transformer 处理。四个输出表示拼接后线性投影为一个骨干输入嵌入，将音频序列速率从 25 Hz 降至 **6.25 Hz**。

### 2.4 投机解码器

MiMo-V2.6 的投机解码（speculative decoding）采用 **MTP 模块**，并遵循 DFlash 的块扩散（block diffusion）设计。草稿模型（drafter）由 **5 层**使用稠密 FFN 的 Transformer 组成。以骨干隐藏特征与干净的锚点 token 为条件，单次前向预测后续 **7 个 token**，供骨干并行验证。所有草稿层使用带分组查询的 SWA，以限制注意力计算与 KV cache 大小。token 在草稿块内双向注意，并可注意锚点之前至多 **1,024** 个骨干上下文位置。

## 3. 预训练

### 3.1 预训练设置

MiMo-V2.6 预训练语料覆盖文本、视觉与音频。文本来自公开网页、书籍、学术论文、代码与 STEM 材料等；视觉包括图文描述、定位、OCR、GUI、对话、视频与视觉编码数据；音频则大规模整理高质量数据，组织为语音–文本交错、自动语音识别（ASR）与通用音频描述三种任务格式。

采用**两阶段预训练**：第一阶段仅用文本训练语言骨干，建立强语言能力；第二阶段接入自研预训练 ViT 与音频编码器，在全模态数据上联合训练，使模型理解图像、视频与音频。

上下文长度从 **32K** 开始，训练中途扩展到 **256K**。MiMo-V2.6-Flash 共训练 **48T** token（文本 26T + 全模态 22T）；MiMo-V2.6-Pro 共训练 **30T** token（27T + 3T）。预训练使用 **AdamW** 优化器。

### 3.2 中期训练设置

预训练建立跨文本、视觉、音频的广博知识与通用理解；**中期训练**则通过进一步发展智能体能力、扩展长上下文支持、并适配大 batch 训练的优化设置，把通用基础桥接到后续大规模 RL。

我们在多样、以智能体为中心的数据混合上训练 MiMo-V2.6：任务域与模态均多样，结合编码、通用、视觉、研究任务的真实智能体轨迹，以及高质量文本、仓库级代码、图像/视频/音频数据。训练分两阶段：先以 **256K** 上下文训练（占大部分算力），最后阶段扩展到 **1M**。

基座模型预训练使用 AdamW，但初步实验显示混合任务 RL 中 batch 增大后优化效率下降。与逐元素自适应的 AdamW 不同，**Muon** 对隐层权重矩阵的更新做正交化，利用矩阵结构（Jordan et al., 2024）。这种基于矩阵的更新在超过临界 batch 后仍保持更强数据效率，适合大 batch 训练。因此中期训练对隐层权重矩阵切换到 Muon 变体 **Muown**，为后续大 batch RL 做准备。Muown 在 Muon 上增加显式行范数控制，缓解谱范数漂移、降低对 weight decay 的敏感度，开销可忽略（Lion et al., 2026）。嵌入、LM head 与 MoE 路由器继续使用 AdamW。

有工作报告从 Adam 预训练切到 Muon 会造成优化器失配与性能下降（Qu et al., 2026），但我们在中期训练全程**未观察到 loss 尖峰**。中期训练还采用 **MXFP4 量化感知训练（QAT）**，使模型适应低精度计算并保持质量。

## 4. 扩展强化学习

本次发布继续推进后训练算法边界，重点是**扩展 RL 计算**。在短暂监督微调（SFT）之后，我们沿训练计算（§4.1）、环境与 harness（§4.2）、评分计算（§4.3）三个维度扩展 RL。

### 4.1 扩展 RL 训练计算

我们在单次运行中扩展到数千张 GPU：MiMo-V2.6-Pro 与 MiMo-V2.6-Flash 的 RL 后训练分别花费约 **260 万美元**与 **90 万美元**。使用大训练 batch：**1,568** 个 prompt，组大小 \(G=16\)，每步 rollout 约 **25K** 条序列，对应 **2.7B–3.7B** 训练 token（每条约 110K–150K token）。

图 3 左图显示扩展 RL 计算的收益：DeepSWE 上 average@3 随累计成本稳步上升——RL 过程中 Pro 从 **58.4 → 72.6**，Flash 从 **48.7 → 65.7**。计算分为 rollout、评分、训练三部分。

**RL 学习目标（式 1）：**

\[
\mathcal{L}(\theta)= -\mathbb{E}_{q\sim\cup_d D_d,\ \{o_i\}_{i=1}^{G}\sim\mu_{\theta_{\text{old}}}(\cdot\mid q)}
\left[
\frac{1}{\sum_i |o_i|}
\sum_{i=1}^{G}\sum_{t=1}^{|o_i|}
r_{i,t}\, M_{i,t}\, A_i \log \pi_\theta(o_{i,t}\mid q, o_{i,<t})
\right]
\]

其中 \(r\) 为重要性采样比率，\(M\) 为 token 级 mask，\(A\) 为优势（advantage）。计算可分解为：

1. **Rollout**：从任务数据并集采样 prompt \(q\)，由 rollout 策略 \(\mu_{\theta_{\text{old}}}\) 生成 \(G\) 个候选解 \(\{o_i\}\)；
2. **Grading**：投入额外算力做智能体评估，超越二值测试结果，区分有效与有缺陷的解/行为，得到优势 \(A_i\)，实现更准的信用分配；
3. **Training**：收集的 token 经 \(\log\pi_\theta(o_{i,t}\mid q,o_{i,<t})\) 的梯度更新 \(\theta\)，采用 prompt-mean 聚合。

图 3 右图：Pro 的成本构成约为 rollout **43.8%**、训练 **43.5%**、评分 **12.7%**。大 batch 在一次运行中覆盖多样 RL 任务、环境与 harness，并扩展评分器以提供细粒度信号。

大 batch 有利于横向扩展 GPU：rollout 按序列并行，训练按数据并行切分 batch。HBM 主要被运行中 batch 占用时，rollout 仍可保持较高算术强度。由于 rollout 与评分存在长尾，使用**部分 rollout（partial rollout）**保持运行 batch 饱满：收集训练 batch 时中断在途序列，并在下一 rollout 阶段继续。代价是 re-prefill：策略更新后需重建 KV cache，因此 batch 大小与 partial rollout 需联合选择，大 batch 可摊薄 re-prefill。

为支持稳定 RL 训练，通过 **R3** 与 **top-p 采样候选集合回放**确保训练–推理一致性。为保证样本都有有效梯度，引入**动态采样器**过滤全对/全错组。多任务 RL 中实现 **Sample Mixer**，在不同任务 rollout 时长与通过率下保证训练 batch 分布高效稳定。将 rollout 轨迹打包为 2.7B–3.7B token 的大训练 batch 时，**解耦数据面与控制面**（详见 §6）。

### 4.2 扩展 RL 环境与 Harness

扩展智能体 RL 需要多样环境：反映真实任务、支持训练规模可复现执行、奖励与任务目标对齐。真实工作流涉及异构工具与复杂状态，自动评分器可能不完整、不一致或可被利用。因此我们在编码、通用专业工作流、视觉产物、网络安全四个方向大规模合成与筛选环境（§4.2.1–4.2.4），强调监督质量；并描述智能体交互所用 harness（§4.2.5），以及执行检查、基于 rollout 的审计与对抗测试（§4.2.6），以提升奖励可靠性、缓解奖励作弊。

#### 4.2.1 代码智能体任务

编码任务特别适合 RL：候选解可执行并通过自动化测试评估，便于规模化反馈。但可执行评估本身不保证可靠监督：测试可能漏掉必要行为、拒绝合法实现，或跨次执行结果不一致。核心挑战是**在扩展任务构造的同时保证奖励忠实反映任务正确性**。

**可扩展任务合成（五条互补路径）：**

1. **基于 GitHub 的合成**：收集 PR 与关联 issue，用启发式与模型辅助过滤去重、去畸形、去不可复现候选。若 issue 对预期改动描述充分，则用作任务规格；否则用 LLM 从参考补丁与仓库上下文重建 issue 式规格，并明确指示**不得泄露实现细节**。
2. **日常工作流**：收集组织内部员工贡献的真实开发请求，覆盖功能实现、重构、调试、仓库维护等；由智能体生成并实现测试用例，把请求行为可操作化。
3. **规格驱动编码**：在详细、多约束需求下评估模型能否忠实把复杂规格译为可执行实现。
4. **源码驱动合成（CodeMidas 等）**：从现有代码库中已实现的功能派生任务——智能体识别候选功能，把可观察行为译成任务规格与可执行环境；无需 issue/PR 等开发工件，即可跨多样仓库扩展任务。
5. **长时程软件工程**：智能体迭代细化需求、扩大改动范围、引入组件间依赖，并构造覆盖多步行为的测试；另结合公开来源与授权数据供应商样本，覆盖广泛语言、开发场景、实现复杂度与时程。

**监督准确性：** 将任务规格的**行为范围**与单元测试对齐——接受满足规格的实现、拒绝违反规格的实现，且不要求参考实现的偶然细节。审查覆盖不足与过严检查；若测试强制了规格中不存在的要求，则修订或删除。仅靠人工审阅可能漏掉规格–测试偏差，因此进一步用**基于 rollout 的审计**评估对齐：每个任务由编码智能体尝试 **4 次**；审计智能体在同一工作区中查看问题陈述、测试、参考补丁，以及每次提交的补丁、测试输出与完整对话日志。审计器先阐述正确解需要什么、测试是否覆盖这些要求；再依据规格评估每个提交解，并与观测奖励比较。**通过但被判定错误** → 潜在假阳性（验证不全）；**失败但被判定正确** → 潜在假阴性（测试过严或执行失败）。这些分歧指向需复核的任务，并给出预期行为与实现验证可能失配的具体证据。

**监督鲁棒性：** 通过重复执行检查奖励稳定性。对带参考补丁的任务：应用补丁前，fail-to-pass（F2P）测试必须失败、pass-to-pass（P2P）必须通过；应用补丁后两者都须通过。要求这些结果在 **8 次重跑**中保持稳定，以筛查 flaky 测试与环境导致的奖励波动。复用 rollout 管道收集轨迹，调查潜在奖励作弊：提交补丁与对话日志揭示智能体如何获得奖励，帮助发现捷径或对环境/评估过程的利用。

规格–测试对齐针对奖励信号的**保真度**，重复执行检查其**稳定性**，rollout 审计探测其是否与独立的正确性判断一致。目标是让该组合可扩展，使 RL 在广覆盖任务上受益，同时鼓励智能体满足预期要求而非钻评估空子。

#### 4.2.2 通用智能体任务

把智能体能力扩展到多领域真实专业工作流：分析异构文档、使用专业软件、产出符合领域标准的交付物。

**环境设计：** 通常由工作区 + 一组软件工具构成，经 MCP、API、CLI、GUI 等接口访问。设计在**真实性**与**大规模 RL** 之间平衡：文件、软件行为与底层数据应反映专业实践，同时执行须本地化、环境易重置。收集真实文件直接纳入或作为合成参考；用自动化多智能体工作流构建**本地软件 mock**，复现支持的操作、状态变化、输出格式与错误响应。已可离线运行的工具直接接入。全部状态本地保存，每次 rollout 在可恢复到固定初态的隔离沙箱中运行，避免网络波动与服务限额，支持可复现执行。

**环境合成：** 规划智能体指定工作区结构、选择工具、规划文件与数据库内容；Web 搜索为计划提供现实依据；文件之间、文件与数据库记录之间的关系支撑后续多跳推理与交叉验证。多个智能体按共享计划与各 mock 的数据规格**并行**生成文件与填充数据库。审查智能体检查单件产物与全局一致性（实体名、数值对账、时间线、引用），迭代修复后再构造任务。

**任务合成与验证：** 调研常见专业任务并合并、泛化为种子任务；智能体探索环境，按内容与工具构造任务。用**原子二值 rubric** 评估完成度：代码检查验证确定性属性（数据库数值、交付物格式），LLM 检查评估更开放的内容。对 LLM 判据，同一模型重复判断与不同裁判模型之间的一致性有助于发现歧义。一致性本身不足以说明 rubric 覆盖了任务完成，因此收集不同能力水平模型的 rollout，由审查智能体检查轨迹、执行结果与 rubric 判定，修订过严/过松标准。为检验抗奖励作弊，加入“未预期改动无关文件/数据库”的负向检查，并构造看起来正确、实则未解题的对抗解。RL 期间使用自托管 MiMo-V2.6-SFT 作为 grader，保证评分稳定。由此得到数千环境与多样可验证任务，与其他任务合并用于 RL。

#### 4.2.3 视觉智能体任务

让智能体通过创意表达与精确视觉控制塑造数字世界。任务覆盖网站、交互应用、游戏、3D 场景、幻灯片、SVG、视频与 Figma 设计等产物，组织为互补两类：

1. **开放式设计**：产出满足用户意图、审美有说服力的视觉产物。有效创意解多样，固定规则难刻画审美。因此结合 **pointwise 与 groupwise 评分**：先迭代细化逐点 rubric（运行时正确性、指令遵循、布局完整、基础审美），稳定后引入**组级评分**，对同一 query 的一组渲染产物联合比较，区分明显更强/更弱候选并给奖。
2. **高保真视觉复现**：忠实复现指定视觉目标。有显式参考，可更直接评估视觉保真。主要用**基于规则的相似度**（渲染产物与参考的像素级相似等），辅以 LLM 整体视觉评审。二者共同支撑视觉复现任务上的 RL 扩展。

#### 4.2.4 网络安全智能体任务

在**真实漏洞复现**上用 RL 训练网络智能体：给定项目与目标 bug，构造能触发它的输入。这是利用开发、权限提升与 CTF 的基础进攻技能，也适合规模化 RL——OSS-Fuzz 提供数万个人工确认实例。难点不在“触发崩溃”（复杂 C/C++ 项目有大量可达崩溃路径），而在触发**特定漏洞**。验证必须把目标 bug 与无关崩溃分开，且作为 RL 奖励须**准确、确定、廉价**。

现有 oracle 不足：CyberGym 等的 fix-binary 差分测试（崩溃脆弱二进制、不崩溃已修补二进制）在补丁不完整或两 commit 间无关变化时会误判，污染训练梯度；LLM 判定对同一 PoC 跨次结论不一，不能作稳定奖励。

我们改为从**真实 sanitizer（ASan/MSan/UBSan）报告**提取两属性：**漏洞类型**（如 heap-buffer-overflow）与**崩溃位置**（最上层项目级栈帧）。当且仅当 PoC 崩溃在规则字符串匹配下二者皆符，才接受——确定、可复现、计算开销极小。任务描述派生自同一报告，写明必须发生的崩溃类型与函数，使**描述与验证共享单一真源**（CyberGym 的 LLM 生成描述往往过宽或有误）。

对每个漏洞，在报告 commit 检出源码、构建 fuzzing harness，并给智能体完整运行环境（全部源码 + 编译好的 harness 二进制）。CyberGym 不提供二进制、限制为纯源码分析；提供二进制更接近真实漏洞分析（调试器运行、检视内存、基于运行时观察构造变异）。

#### 4.2.5 多 Harness 训练

Harness 在模块设计上不同，服务不同应用需求。模型须适应多样交互机制，包括训练中未见过的 harness，因此**跨 harness 泛化**是重要能力。只在单一 harness 内训练，可能把解题策略耦合到特定实现、限制迁移。故将 harness 多样性与任务/环境多样性并列为训练维度。

直接在 MiMo Code、Codex 等**生产 harness** 上训练并不适合 RL：其一，生产 harness 在智能体循环外包裹工程防护与多步工作流，并用大量约束/指令 prompt 引导模型——这些额外内容不在任务完成奖励信号内，信用分配不可靠，奖励未度量的要求会被忽略；其二，模块紧耦合、难以独立配置，无法单独改变某一交互机制或通过可控重组组装多样性。

因此提出**多 harness 训练**：使用精心解耦、可配置的 harness 组件，系统改变交互机制，提升泛化并改善信用分配（详见原文对模块分解与训练混配的描述）。

#### 4.2.6 执行检查、审计与对抗测试

在训练前与训练中结合：

- 执行一致性检查（重复运行检测 flaky 测试）；
- 基于 rollout 的奖励审计（规格–测试对齐、行为检查）；
- 对抗测试（故意构造易诱导奖励作弊的环境/评分缺陷并修复）。

目标是在扩展环境规模的同时，尽量保证奖励可靠、抑制 reward hacking。

### 4.3 组级智能体评分

传统做法对通过同一测试集的所有解赋予相同二值奖励，难以区分“碰巧通过”与“高质量、高效率”的解。**组级智能体评分**在同一 prompt 的 \(G\) 个候选之间比较质量与行为，再把细粒度差异转为学习信号。

**主要思想：**

1. 对组内每个候选做更丰富的智能体评估（过程、正确性、效率等）；
2. **Groupwise Reward Synthesis (GRS)**：合成组内相对奖励，使同组解获得可比较的分数，而非一律 0/1；
3. **Groupwise Advantage Redistribution (GAR)**：把合成后的差异再分配到轨迹/步级优势，指导模型偏好更准确、更 token 高效的解（例如更短的正确解优于冗长的正确解）。

这样，在长时程任务上信用分配更细，并可显式激励**更短、更省 token** 的解法。原文给出具体合成函数、超参与消融（请对照 PDF §4.3 与实验表）。

## 5. 实验：You Only RL Once

### 5.1 训练设置

在较短 SFT 后，沿 §4 三个维度扩展 RL。主要结果展示“一次大规模 RL”即可在多域持续提升（图 1）。成本与 batch 设置见 §4.1。

### 5.2 评估设置

覆盖编码（DeepSWE v1.1、SWE-Bench Pro、MiMo Code Bench）、通用工作流（AutomationBench v1.0.6）、视觉设计（MiMo Visual Coding）、网络安全（MiMo Cyber Bench）等；指标含 average@3 等（以原文评估协议为准）。

### 5.3 RL 性能

MiMo-V2.6-Pro 与 Flash 随 RL 步数增加，在上述基准上稳定提升；收益跨域一致，反映更通用的智能体能力（图 1、图 3）。

### 5.4 冻结路由器以稳定 RL

在大规模 MoE RL 中，我们**冻结 MoE 路由器**，以降低训练不稳定与路由分布漂移风险，保证扩展过程可控。该选择与多层反 reward-hacking 防御共同构成稳定训练策略（详见原文消融）。

### 5.5 RL 失败分析

对失败案例进行分类（环境/评分缺陷、探索不足、奖励作弊苗头、长时程信用分配误差等），并据此迭代环境与评分（原文 §5.5 提供具体分析）。

### 5.6 通过 MOPD2 拓宽能力

在 RL 主线之外，使用 **MOPD2（Multi-Teacher On-Policy Distillation 变体）** 将多领域教师能力合入学生，在保持 RL 收益的同时拓宽能力覆盖面（与 MiMo-V2 系列中的 MOPD 思路一脉相承，详见原文 §5.6）。

## 6. RL 与 OPD 基础设施

### 6.1 具有细粒度学习信号的智能体 RL

统一轨迹表示、token/turn 级 mask 与优势字段，使多 harness、多模态负载的轨迹都能进入同一训练管道，并配合惩罚机制细化学习信号。

### 6.2 Harness Pool 与 Payload Porter：多 Harness 大 Batch RL

- **Harness Pool**：维护多种智能体框架的高并发交互池；
- **Payload Porter**：搬运携带路由与多模态负载的海量轨迹，支撑 2.7B–3.7B token 级训练 batch。

### 6.3 Sample Mixer：稳定的异步混合任务 RL

动态采样 + 部分 rollout + Sample Mixer，稳定各任务在训练 batch 中的样本构成，避免长尾任务饿死或短任务刷屏。

### 6.4 训练/推理一致性与优化

在 MoE 路由与 top-p 采样候选集合上对齐训练引擎与推理引擎，并针对 RL 负载优化两端（吞吐、KV cache、调度等），降低 off-policy 偏差与数值不一致。

## 7. 面向智能体 RL 的开放基础

### 7.1 从 MiMo-V2.6 蒸馏

开源轻量模型 **MiMo-V2.6-Distill-Qwen-9B**（基于 Qwen 系列蒸馏/适配），用于可复现的智能体 RL 研究与教学实验。

### 7.2 在开放环境上做 RL

开源：

- 多领域**任务环境与验证器**；
- **端到端 RL 训练框架**；
- 可组合 **mini-harness**。

配套实验表明，在多样任务与 harness 上 RL 均有一致收益，可作为社区公平、强健、可复现的基线，降低复现与扩展大规模 RL 的工程门槛。

## 8. 结论

MiMo-V2.6 通过混合 SWA–GA 稀疏 MoE 骨干、全模态预训练/中期训练，以及在训练计算、环境/harness、评分计算三个维度上扩展 RL，展示了通往模型自我改进的可行路径。冻结路由器与反奖励作弊防御保证了扩展稳定性；组级智能体评分提供了超越二值测试的细粒度信号；统一轨迹与异步混合任务基础设施支撑了超大 batch 的智能体 RL。我们开源模型、环境、框架与 harness，希望推动递归自我改进方向的开放研究。
