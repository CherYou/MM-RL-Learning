# 证据与验证层级

本仓库区分四种验证状态。README、章节正文、日志与 PR 描述中的“通过 / 复现 / 可运行”必须能对应到下表，不得把较低层级写成较高层级。

| 层级 | 含义 | 典型入口 | 不能声称 |
| --- | --- | --- | --- |
| **L0 数学演示** | 构造张量核对 loss、梯度、概率方向 | `examples/math/loss_walkthrough.py`、`arl loss-demo` | 模型学会任务 |
| **L1 机制 smoke** | tiny 模型 / fixture / 真实代码链路可执行 | `python <chapter>/train.py --smoke`、`arl train … --smoke` | GSM8K / 论文指标提升 |
| **L2 小任务学习** | 可控任务上训练前后有独立评估变化 | 具身 FetchReach 短程实验等 | 标准 benchmark 或论文复现 |
| **L3 方法复现** | 明确模型、数据、预算、硬件下与原文/基准可比 | 固定配置的 GPU 实验与证据包 | 因某次 loss 正常即宣布复现 |

## 常见混淆

| 现象 | 正确表述 |
| --- | --- |
| `--smoke` 两次更新结束 | L1 管线可执行 |
| debug reward 或 tiny 模型 loss 下降 | 机制在优化；非任务能力 |
| L0 脚本 `"status": "passed"` | 构造数学检查通过 |
| verl GPU 三步训练 + checkpoint 重载 | 特定配置下的 L1/L2 机制证据；非论文分数 |
| 具身 smoke 使用真实 MuJoCo 奖励 | 与 LLM fixture 不是同一类实验，仍需独立评估才谈 L2 |

## 章节证据卡（建议字段）

贡献涉及实验结果时，请在 PR 或章节 README 补充：

- 算法 / 配方定位与本地差异
- 后端、模型初始化、数据来源与 revision
- 预算（步数、采样数、有效 token、环境步 vs 梯度步）
- 验证层级与运行日期
- 日志或报告路径（`runs/`、`reports/` 默认可不入库，但公开结论应可复核）
- **未验证部分**

## 数据类型标注

| 数据 | 用途 | 必须写明 |
| --- | --- | --- |
| 人工构造张量 | L0 数学 | 不是模型实验 |
| fixture / scripted trajectory | L1 机制 | 不冒充自主解题 |
| 学习子集 | 降低上手成本 | 与完整 benchmark 的差距 |
| 合成偏好对（如 DPO） | 接口与 margin | 负例构造方式与长度捷径 |
| 官方划分 | 可比实验 | 版本、过滤、是否保持协议 |
| 本地仿真采集（具身） | 控制/离线 | 采集器、步数、训练/评估隔离 |

## CI 中的“跳过”与“通过”

缺少 GPU、ALFWorld 或 verl 环境时，相关 job 应显示 **skipped / not configured**，不得静默变成绿色的能力验证。外部链接检查失败应单独报告，避免网站抖动阻塞数学测试。
